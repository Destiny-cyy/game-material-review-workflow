# 分析口径与结论写法（analysis-playbook）

> 现行口径。**打标 → 按本文件口径分析 → 按 `report.narrative` 叙事输出报告**。
> 本文件不含任何真实业务数据；出现的数字一律是占位 `X.XX%` / `N` 或标注「示例」。

---

## 一、口径声明（每次交付物开头必备）

```
口径：<唯一创意图 N 张 / 投放记录 M 条，二者关系说明>
区间：数据覆盖 YYYY-MM-DD ~ YYYY-MM-DD（若大盘数据区间不同，单独注明）
来源：在线表格「<文档名> → <子表名>」，原表只读未改动
打标：多模态逐张看图判读 N 张唯一图；置信度"中"的待人工复核
```

> 真实教训（已抽象）：业务方曾把「M 条投放记录」当成「M 张图」，实际只有 N 张唯一图。**每次交付主动说明，别等对方问。**

**两条铁律**
1. CTR 一律用**投放记录口径**（SUM 点击 / SUM 曝光）。唯一图口径只用于复用衰减分析。
2. 任何结论必须带三个数：**样本量 / 曝光量 / CTR**，缺一不可。

---

## 二、CTR 计算口径

```
CTR(组) = SUM(组内所有记录的点击) / SUM(组内所有记录的曝光) × 100%
```

**禁止简单平均**：`mean(每条记录的 CTR)` 会让大曝光记录被稀释、小曝光记录被放大，
一条大曝光素材和一条小曝光素材对整体贡献完全不同，简单平均会让噪声主导结论。

**样本量门槛**（取值来自 `thresholds.min_sample`）
- 样本 < 门槛：标注「样本不足」，只给方向性结论（"似乎""倾向"），不给具体数字对比
- 样本 ≥ 门槛且曝光充足：可给正式结论
- 样本够但曝光偏小：给结论但标注「曝光量小，需谨慎」

## 三、分析维度（六 + 一）

| # | 维度 | 分组依据 | 用途 |
|---|---|---|---|
| 1 | 整体月度 | `date[:7]` | 看趋势、找环比变化 |
| 2 | 节点 | `nodes` 规则 | 哪些档期值得加投 |
| 3 | 用户分层 | `segment` | 人群效率差异（见 `user-analysis.md`） |
| 4 | 画风 | `style` 单选 | 指导设计风格选择 |
| 5 | 画面元素 | 多选**包含**口径 | 识别高效元素组合 |
| 6 | 福利呈现 | `benefit` 单选 | 验证「加福利」策略是否有效 |
| 6b | 画风 × 福利交叉 | 两维组合 | 找最优组合（交叉组样本易不足，务必标注） |
| 7 | 复用衰减 | 唯一图口径 | 老图反复投还有没有效 |

**多选元素的关键**：不能用等值分组，必须用「包含」口径逐项筛，一条记录可同时计入多个元素组；
**结论里要说明组间样本重叠**。

## 四、第七维度：素材复用与衰减

**为什么单列**：投放记录 ≠ 创意图。一张图会被多条记录复用，只看记录维度会掩盖「老图反复投还有没有用」。

**做法**（`scripts/reuse_map.py`）：
1. 按图片链接把投放记录去重成唯一图，一条记录 = 一次复用
2. 每张图合并算加权 CTR、总曝光，按复用次数分档
3. 看两件事：
   - **衰减曲线**：各档 CTR 中位是否随复用次数下降
   - **曝光结构是否倒挂**：低效率档（复用多）是否反而吃掉大部分曝光

**结论写法**：复用控制在 N 次以内；缺口应补在新图上，而不是反复复用老图。样本 < 10 张的档位标注「样本极小，仅参考」。

> ⚠️ 复用分档只是**相关性，不是因果**：也可能是「好图才被复用多次，但投到后面人群疲了」。下结论留这个余地。

## 五、大盘 Benchmark（双口径，必做）

### 做法
1. 取大盘表，按「游戏名 × 月份」聚合曝光与点击
2. **先 `GROUP BY 游戏名` 看全部变体，用 `benchmark.aliases` 合并**后再算
3. 算各游戏曝光加权 CTR、降序排名，定位目标游戏名次与分位
4. 同时给出当月**中位数**与 **top 25% 线**，判断水位

### 两个口径都要算
| 口径 | 分母 | 反映什么 | 用途 |
|---|---|---|---|
| 游戏级 | 曝光加权 | 整体投放效率 | 看大盘位置 |
| 素材级 | 单张中位 | 单张素材质量 | 看设计水位 |

**两个口径可能矛盾**：游戏级高但素材级低 = 靠爆款/档期堆量；游戏级低但素材级高 = 素材好但量不够。
**只看游戏级会误判**——整体好看可能掩盖素材平均水准偏弱这个真瓶颈。

### 四个必踩的坑
| 坑 | 处理 |
|---|---|
| 游戏名变体 | 先 `GROUP BY 游戏名` 看全部变体，`aliases` 合并，否则算出 CTR≈0 的假结果 |
| 大盘表月份覆盖不全 | 对比区间按大盘表实际范围写，别拿 4 个月数据比全年 |
| 只看游戏级 | 游戏级 + 素材级都算，后者才是真瓶颈 |
| 分位算不出来 | 在线 SQL 可能不支持窗口函数，改为拉明细到本地算分位 |

**参评门槛**：游戏级按月曝光 ≥ `benchmark.game_min_impressions`，素材级按单条曝光 ≥ `benchmark.material_min_impressions`，避免小样本刷榜。**同时给分位与中位对比**，不要只给排名。

## 六、结论写法模板

### 单维度结论
```
【画风·<取值>】CTR X.XX%（样本 N 张 / 曝光 XXw）
  vs 大盘中位 X.XX%（+/-X.XXpp）
  vs 对标游戏同维度 X.XX%（曝光 XXw，我方曝光 XXw）
  结论：该风格表现[最优/中等/待优化]，建议[加大/维持/减少]投放。
```

### 环比/对照实验结论（优先使用）
```
【福利呈现·环比进步】
  前期：约 X% 无福利，CTR X.XX%
  后期：全面加福利，CTR X.XX%
  结论：加福利后 CTR 环比 +XX%，验证策略有效，建议持续。
```
> 好的叙事是「改了什么 → 好了多少」这种干净的因果故事，而不是排名羞辱。

### 结论四要素（缺一不可）
1. **标签**：哪个维度、哪个取值
2. **CTR**：曝光加权后的数字
3. **对比基准**：大盘中位 / 对标游戏 / 环比基线
4. **幅度**：差值（pp）或倍数

优先级分三级：**第一杠杆 > 次要因素 > 暂缓方向**；行动建议必须可执行（做什么 + 参考哪条素材 + 优先级），并列出**暂缓清单**。

## 七、缺口测算口径

```
月需求 = 投放天数 × 每日差异化张数（通常 2-3）
可复用 = 现有套数中历史验证高 CTR 的底稿数
净缺口 = 月需求 − 可复用
```
必须写明三条假设：①每日差异化张数 ②老底稿复用率 ③是否含版本换新缓冲。
缺口测算只给**方向性**结论，不承诺精确数字。

## 八、叙事原则与对外脱敏对照

报告写什么由 `config.report.narrative` 决定。用 `positive_only` 时遵守：

- 只写**有优势的、环比进步的**内容；「全周期垫底」「X 分位」「末位」等表述不进报告
- 大盘对比**只保留中位数作参照**，不列头部游戏名
- 对标游戏对比**必须同时给曝光量**；某维度无优势就删掉该对比，宁可少写
- 排名/分位/垫底等数据**仍要算出来留档**，交付时口头/私信告知业务方本人

### 对外脱敏对照表（简历 / 外部分享必用）
| 内部措辞（不要写） | 对外改写 |
|---|---|
| 曝光绝对值（如 X 亿） | 「亿级曝光」「近 N 个月全量投放数据」 |
| CTR 点数值（如 X.XX%） | 「约为大盘中位的 2-3 倍」「进入平台前 X%」 |
| 分层 CTR 具体值 | 「老用户效率约为纯新进的 N 倍」 |
| 资源金额（X 万 → Y 万） | 「投放资源扩容约 N 倍」 |
| 消耗 / 收入类 | 一律省略 |
| 「全周期垫底」「X 分位」 | 「有提升空间」「与大盘中位存在差距」 |

**原则**：CTR 用**倍数 / 百分比差异 / 排名**；曝光与金额用**量级 / 倍数**；不展开平台内部指标口径；游戏名可写，具体数字不写。

## 九、交付物清单（每次复盘输出）

1. **HTML 复盘报告**：按叙事策略输出，维度全覆盖，结论四要素齐全
2. **在线智能文档**（可选）：HTML 报告的在线版，方便转发
3. **tagged.csv / analysis.json / benchmark.json / reuse_map.csv**：内部留档
4. **口径声明**：置于每个交付物开头
5. **口头/私信告知业务方本人**：不进报告的扎心数据
