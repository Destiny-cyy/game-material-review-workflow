# 视觉标签体系：怎么建、怎么判、怎么扩展

> 打标前必读。所有标签只依据**画面本身可观测的特征**判定，不依赖广告文案、文件名、投放数据或主观猜测。
> 本文件讲的是「建体系的方法」，具体取值一律从 `config.taxonomy` 读；两套示例预设见 `config/presets/`。

---

## 一、为什么需要标签体系

投放后台只有数字，没有「这张图画了什么」。标签体系就是把画面翻译成结构化字段，
让「画风 / 元素 / 福利形式」这些设计语言能和 CTR 拼在一起算。

好的体系要经得起三问：**每张图能不能 unambiguous 地落标签？设计师看到标签名知不知道做什么？分完组样本够不够算？**

---

## 二、维度总览（结构固定，取值可换）

| 维度 | 类型 | 说明 | 配置字段 |
|---|---|---|---|
| 画风 | 单选、互斥穷尽 | 这张图整体是什么美术风格 | `taxonomy.style` |
| 画面元素 | 多选，最多 N 个 | 画面里有哪些可见元素 | `taxonomy.elements` |
| 福利呈现 | 单选 | 奖励/福利信息以什么形式出现 | `taxonomy.benefit` |
| 节点 | 单选 | 由投放日期 + 标题关键词自动映射，不靠看图 | `nodes` |
| 用户分层 | 单选 | 来自源表「广告类型」，不是看图打的 | `taxonomy.segments` |
| 打标置信度 | 单选 | 打标者自评 | `taxonomy.confidence` |

**关键约束**
- 画风、福利呈现、节点、置信度：**单选**，一条记录只能落一个值。
- 画面元素：**多选**，最多 `element_max` 个（默认 3）；超过说明素材信息过载，取视觉占比最大的几个。
- 节点由规则自动映射，**打标时不需要人工判断**；档期日期每次复盘前必须向业务确认。
- 用户分层沿用源表口径，需与 `taxonomy.segments` 取值一致。

---

## 三、四条建体系标准（新增/扩展前必答）

1. **是否互斥？** 单选维度下，新类别与现有类别必须互斥；多选维度允许共存。
2. **只看画面可判？** 是否需要读文案、看数据、凭主观感觉才能判？需要 → 不合格。
3. **设计师可执行？** 看到类别名能否直接理解要做什么？需要额外解释 → 命名不合格。
4. **拆分后样本是否 ≥ `thresholds.min_sample`？** 按历史数据估算；不够就先合并到相近类别，等样本积累再拆。

**四问全过才允许扩展。** 扩展后同步更新 `config.taxonomy` 与 `config/presets/`，并保证 `write_smarttable.py` 生成的选项一致（它读 config，不用改代码）。

## 四、判定优先级与边界处理（通用套路）

不同品类的取值不同，但**处理边界的套路是通用的**，建自己体系时照这个思路写判定标准：

### 1. 画风：先判「形式」，再判「风格」
```
是不是实机截图（有 UI/HUD）？ → 是 → 归「实机」类
是不是纯场景概念图（角色很小）？ → 是 → 归「场景原画」类
否则 → 在 CG/插画里按色调、明暗、质感分风格
```
写清每类的**画面特征 / 色调 / 典型元素 / 反例**，尤其要写「什么情况不算这一类」。

### 2. 画面元素：按视觉占比取前 N
- 只标画面里**真的看得见**的东西，不硬凑。
- 「大字文案」「奖励物」「实机」这类是常见组合项。
- 元素维度与画风维度各自独立标记，允许重合（例如一张图既是「实机」画风，又带「实机」元素）。

### 3. 福利呈现：先判「形式」，与「元素」区分开
- 「画面里有没有奖励物」是**画面元素**；
- 「奖励物怎么摆」是**福利呈现**。
- 例如「一张显卡海报」= 元素[奖励物] + 福利[单品聚焦]。这两个维度别混。

### 4. 判定优先级写成明确顺序
给每个单选维度写一条优先级链（如「实机 > 场景原画 > 华丽风 > 暗黑风 > 写实风」），
遇到两可情况按链取第一个命中的，避免不同人打出不同标签。

### 5. 置信度
| 等级 | 判定 |
|---|---|
| 高 | 特征清晰、无歧义 |
| 中 | 有 1 处边界模糊但已选定 → **进人工复核清单** |
| 低 | 画面模糊 / 信息不足 / 多处模糊 → 仅供参考，或标「待人工」 |

分析时默认纳入全部置信度；若某维度结论不稳，可只看「高」子集做敏感性检验。

## 五、同一张图被多次投放怎么打

- **图片链接相同 = 同一张图**，只打一次标签（用首次出现的那张）。
- 分析时按图片链接去重成唯一图；打标结果再回填到所有复用记录。
- 见 `analysis-playbook.md` 的「复用衰减」维度。

---

## 六、常见反模式（别这么干）

- ❌ 用广告标题/描述里的词推断画风（标题写「暗黑」不代表画面是暗黑）
- ❌ 类别拆太细，一半组样本个位数 → 结论不可信
- ❌ 单选维度类别不互斥（一张图能同时落两个画风）
- ❌ 把「有没有奖励」和「奖励怎么摆」塞进同一个维度
- ❌ 把版本号、修订史写进对外文档（见 `doc-sync.md`）
- ❌ 把标签取值写死在脚本里（本包要求一律走 config）

## 七、两套示例预设怎么用

`config/presets/preset.A.json`（偏暗黑幻想 / ARPG）与 `preset.B.json`（偏科幻 / 射击）
演示的是**同一套流程、两套标签**：画风取值完全不同，但脚本、分析维度、报告模板一模一样。

用法：在 `config.json` 里加一行 `"preset": "preset.A.json"`，`config_loader.py` 会自动合并；
也可以直接把 preset 里的 `taxonomy` / `nodes` 拷进 `config.json` 自己改。
**它们只是示例，不是任何真实项目的口径。**
