# 用户分层与受众分析（对应「用户研究 / 用户分析」）

> 说明：本包里**没有**一个单独的「用户研究」工具，这块能力长在素材复盘流程里——
> 用「人群分层 × 素材标签 × CTR」的交叉分析，回答「哪类素材打动哪类人」。
> 本文件把这套方法单独抽出来讲清楚，方便单独复用。

---

## 一、先分清：这里能做的和不能做的

| 能做的（有投放数据就行） | 不能做的（需要别的数据源） |
|---|---|
| 不同人群的效率差异（CTR 倍数） | 用户画像 demographic（年龄/地域/设备） |
| 哪类画风/福利对哪类人群更有效 | 用户访谈、问卷、可用性测试 |
| 人群 × 节点 × 素材的组合归因 | 留存、付费、LTV 等后链路指标 |
| 分层配比建议（资源怎么分） | 归因到具体创意的因果实验（需 A/B 实验设计） |

**定位**：这是「投放效果侧的受众分析」，回答「素材该投给谁、给谁看什么」，
不是完整意义上的用户研究（那需要用研/数据团队的用户画像与调研）。
两者可以互补：用研给的人群定义，正好作为这里的 `segment` 输入。

---

## 二、人群分层从哪来

沿用投放后台的**人群定向口径**，在源表里通常是「广告类型」列，映射到 `fields.segment`。
常见四类（名称按你们平台改，写在 `config.taxonomy.segments`）：

| 分层 | 大白话 | 典型特征 |
|---|---|---|
| 纯新 | 从没接触过的新用户 | 对游戏无认知，需要强信息/强利益点 |
| 包名包 / 回流包 | 圈定的一批号码、可触达人群 | 有一定认知，重召回 |
| 老用户 | 已有账号/历史活跃 | 认品牌、对版本内容敏感，效率常明显更高 |
| 兴趣标签 | 按兴趣定向的泛人群 | 精准度取决于标签质量 |

> ⚠️ 若数据源是 `market_table`（平台大盘表），通常**没有分层字段**，做不了用户分析；
> 需要从广告后台导出补充，或改用 `own_ledger` 模式。

---

## 三、核心方法：三个交叉

### 交叉 1 · 分层 × 整体效率
```
对每个 segment 算 曝光加权 CTR，看倍数关系
结论形态：老用户效率约为纯新进的 N 倍
```
**注意**：分层之间 CTR 差异常常很大，但**不能只看 CTR 就下「多投老用户」的结论**——
老用户盘子小、可投放量有限，CTR 高不代表能放量。要结合曝光规模一起看。

### 交叉 2 · 分层 × 素材标签（最有价值）
```
segment × style / segment × benefit / segment × elements
```
回答「同一类素材，对不同人群是不是一样有效」。
常见发现：某类强视觉素材对纯新有效，但老用户更吃版本内容/福利信息。
**这类交叉组样本容易不足**，务必带样本量并标注「样本不足」。

### 交叉 3 · 分层 × 节点
看档期对不同人群的引爆程度，判断资源该往哪个档期、哪个人群倾斜。

---

## 四、两条铁律

1. **CTR 一律曝光加权**（SUM 点击 / SUM 曝光），不对每行平均。
2. **人群效率对比必须带曝光量**。只给 CTR 不给分母 = 隐藏了「这个人群其实没多少量」，是误导。
   格式：`分层X CTR X.XX%（曝光 XXw）vs 分层Y CTR X.XX%（曝光 XXw）`。

---

## 五、结论怎么写

```
【分层 × 福利】老用户 × <福利形式>：CTR X.XX%（样本 N，曝光 XXw）
  是该分层里最高的组合，约为纯新进同组合的 N 倍
  结论：下轮老用户资源优先配 <该组合>，参考素材 <编号>；纯新进暂不追加
```

优先级给到「**做什么 + 给哪个人群 + 参考哪条素材**」，而不是笼统说「老用户更重要」。

---

## 六、常见误判（都踩过）

| 误判 | 为什么错 | 正确做法 |
|---|---|---|
| 「老用户 CTR 高 → 全投老用户」 | 忽略可投放量上限 | CTR 与曝光规模一起看 |
| 「某分层涨了 → 素材变好了」 | 可能是人群结构变了 | 固定分层内做环比 |
| 「这组合 CTR 最高 → 主推」 | 样本个位数、不显著 | 标注样本不足，只给方向 |
| 把分层当因果 | 人群与素材是相关不是因果 | 下结论留余地，必要时设计 A/B |
| 混用「唯一图」与「记录」口径分层 | 分母错 | 统一用投放记录口径算 CTR |

## 七、和「素材缺口测算」怎么接

受众分析的产出，最终要落到「下轮做什么」：
```
找出 分层 × 标签 的高效组合
   → 判断这些组合现有可复用底稿够不够
   → 不够的组合 = 优先补的新素材方向
   → 排进 P0/P1 优先级
```
这样「用户分析」就不是一份孤立的报告，而是**直接驱动素材生产排期**。
缺口公式见 `analysis-playbook.md` 第七节。
