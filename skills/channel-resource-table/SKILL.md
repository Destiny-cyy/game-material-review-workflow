# 渠道发行 · 资源/素材需求表（通用版）

## 用途

把一个「要在某平台申请资源位、并收集素材」的需求，变成两张可直接使用的在线表格：

| 交付物 | 给谁 | 回答什么 |
|---|---|---|
| **① 全景表** | 自己 / 渠道侧内部 | 平台有哪些资源位？各自什么规则？够不够格申请？对接人是谁？报备进度到哪了？ |
| **② 资源需求表** | 品牌方 / 市场团队 / 合作方 | 要什么？什么规格？什么时候给？往哪填？ |

两张表**必须成对交付**。全景表是内部推演底稿，精简表是拿出去收东西的工具。
不要把全景表直接发给合作方——内容太重，对方看不懂也不知道该干什么。

> 本包为脱敏通用版：示例里出现的平台、专区、游戏一律用「平台 / 专区 / 项目」占位，规则章节号用「X.X」占位。
> 具体平台规则请读你们自己的官方文档后填入。

## 核心判断：先搞清楚「要申请什么」

动手前先把这五件事定下来，它们决定表的行数和列数：

1. **平台与专区**：哪个平台的哪个专区。不同专区规则完全不同，别串。
2. **可用资源位清单**：按平台规则文档列出全部位置，标注常态 / 非常态。
3. **本次申请范围**：明确勾出要申请哪几个。**通常只申请非常态位**——常态位多为自动拉取或系统生成。
4. **申请资格**：按规则逐条套，判定走哪条通道成立、哪条不适用。资格不成立的表做了白做。
5. **素材项**：每个申请位要几样东西，逐项拆开。

## 执行流程

### 第 1 步 · 摸清规则
读平台官方规则文档，摘全：位置清单与常态/非常态分类、名额上限、同期限制、
每类素材的**尺寸/格式/大小上限/字符数**、流程性门槛（报备天数、邮件开通、入库时长）、
内容审核红线、对接人与入口链接。
规则文档若有两份以上，先分清各自管什么，**两套体系别混**。

### 第 2 步 · 判定资格与范围
按规则原文判定申请通道，落成判定表（进全景表）。注意：
- 规则里的**举例通常是举例、非排他**，不要据字面排除其他类型
- 找不出明确依据时标「需运营评定」，不要自己下结论
- 有硬条件的通道把硬条件单独标出——这是最容易漏、漏了整个申请就塌的一件事

### 第 3 步 · 生成全景表
结构见 `references/table-structure.md`，内容规范见 `references/content-principles.md`。
多个子表分区承载：资源位汇总 / 规则与对接速查 / 申请资格与报备进度。
**每条规则都要标出处章节号**，被质疑时能直接翻原文。

### 第 4 步 · 生成精简需求表
只保留三件事：**要什么 · 什么规格 · 怎么交付**。
- 行数 = 素材项数，列数 = 本次需要哪些字段，**行列不固定、自适应**
- 素材三件套拆开写：素材说明 / 规格要求 / 关键规范要求
- 备注列只放对接人、链接、模板提示
- **不写规则背景、名额限制、审核红线**——合作方懂业务，写了反而让表变重
- 留一列空的「交付内容」给对方填

### 第 5 步 · 排交付 DDL
用户给了上架日 T 就倒推每项交期。**核心是分清挂在 T 前还是 T 后**——
从「直播/活动」派生的素材（切片 / 合集）只能挂在 T 之后，这是因果顺序，排错整张表就废了。
方法与锚点见 `references/ddl-planning.md`。

### 第 6 步 · 核查
对照规则文档逐条核规格项，方法见 `references/rule-check.md`。
核完把问题**报给用户，由用户决定改不改**——不要擅自改用户已定稿的表。

## 表格生成方式

**不要走本地文件导入**（会被安全策略拦截）。用在线接口新建空表再写入：

```bash
table-cli doc create --json '{"doc_type":"sheet","doc_name":"<表名>"}'
table-cli sheet workbook get --json '{"docid":"<docid>"}'
python scripts/build_sheet.py --spec config/spec.example.json
```

`scripts/table_sheet.py` 封装全部操作（写入/合并/表格样式/字体/边框/尺寸/验收），
`scripts/build_sheet.py` 读一个 JSON spec 一键生成整张表。优先用脚本，不要手写一堆 CLI 调用。

**动手前先读 `references/table-cli-gotchas.md`**——里面的坑每一个都会让你白跑一轮。

## 硬规矩

- **单元格只填结论，不填理由**。交付 DDL 写「X月X日」就够，不写「为什么这天」。理由在对话里说。
- 用户给的**原始表格 / 在线表一律只读**，禁止修改、写入、覆盖。要验证就新建一张测试表。
- 生成前先确认角色称谓指谁（品牌方 / 渠道 / 平台）再动手，别猜。
- 全景表与精简表的口径必须一致，改一处要同步另一处。
