# 表格结构规范（通用）

## 层级固定五层

行数和列数**不固定**，按每次实际需求自适应。固定的是下面这套层级。

| 层 | 位置 | 内容 | 样式 |
|---|---|---|---|
| L1 大标题 | 第 1 行，合并至末列 | 主题 + 版本 | 18pt 粗体、白字、主色底、居中，行高较大 |
| 说明行 | 第 2 行，合并至末列 | 本次申请什么 + 活动是什么 + 投放去向 | 小字、灰字、浅灰底、左对齐、换行 |
| 分类条 | 第 3 行，跨列合并 | 分段名 | 中号粗体、白字、深色底、居中 |
| 表头 | 第 4 行 | 字段名 | 粗体、深色字、居中、换行 |
| 数据 | 第 5 行起 | 一项一行 | 居中、换行、行高留足 |
| L5 备注 | 末行，合并至末列 | 填写说明 | 小字、灰字、浅灰底、左对齐、换行 |

> 配色可用 `scripts/table_sheet.py` 里的主题常量，或按你们团队视觉规范改。本包示例用蓝色系，仅为占位。

## 分类条

- 列多时（>8 列）**必须加分类条**，否则看不出分组。
- 分类条**必须覆盖所有列**，别漏列、别跳号。
- 分类条若在表格样式范围内，合并会失效（见 `table-cli-gotchas.md`）。
  **做法：分类条所在行留在 `table style` 范围之外**，即表格样式从**表头行**开始。

## 合并

- 同类项**纵向合并**（如资源位按档位合并成一块），组内首行填值、后续留空。
- 扩大合并范围（clear 旧 → set 新）会**清空该格内容**，必须紧接着重写值并重设样式。

## 尺寸

- 列宽：中文全角约 15–18px/字，英文半角约 7–9px/字，左右留 padding。
  单元格超长文本直接给宽列。单列限制在合理区间。
- 行高：**所有实际层级都要显式设**，不要只设数据区。
- 内容放不下才开自动换行并加行高。

## 执行顺序（重要）

1. 写数据（一次 `cells batchset` 写完整区域）
2. `merge set`（先合并，或确保合并区在表格样式范围外）
3. `table style add`（范围 = 表头行 : 数据末行，**不含分类条行**）
4. `style set`（L1 / 说明 / 分类条 / 表头 / 数据 / 备注）
5. `table style update`（带 `tab_style_id`，设边框色）
6. `border set`：先各备注区 `inner_horizontal + inner_vertical`，最后整体一次 `outer`
7. `dims resize` 设行高列宽
8. 验收回读

## 五项验收断言

1. **L1 结构**：标题在 A1，合并到第 1 行末列，回读 `merges` 含完整范围。
2. **表格样式范围**：`table style list` 的范围与计划一致，`has_header` 正确，不含其他层级。
3. **尺寸**：`sheet info get` 回读行高列宽符合计划（稀疏结果时缺失项按默认判断）。
4. **样式与边框**：抽查每个层级代表格；边框色一致；整体外边框只调用一次且 `affected_range` 等于整体范围。
5. **数据不变**：重新读值，确认字段名、单元格值、合并结构未被样式操作意外改变。

**接口返回成功 ≠ 验收通过。五项全部成立才可报告完成。**
