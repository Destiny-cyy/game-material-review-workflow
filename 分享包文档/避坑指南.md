# 避坑指南

> 建议**先看这份再动手**。下面的坑每一个都会让你白跑一轮，都是实际踩过的（已抽象，不含任何真实项目信息）。

---

## 一、口径类（最容易翻车）

### 1. 「投放记录」≠「唯一创意图」⭐ 头号坑
一张图会被多条记录复用（不同人群/日期/位置各记一行）。
把「M 条投放记录」当成「M 张图」是最常见的错。
**每次交付主动写清用的是哪个口径**，别等对方问。打标按「张」打、分析按「记录」加权。

### 2. CTR 必须曝光加权，不能简单平均
`SUM(点击)/SUM(曝光)`。简单平均会让小曝光素材的噪声主导结论。
每个结论带 **样本 / 曝光 / CTR** 三个数。

### 3. 大盘对比必须双口径
游戏级（曝光加权）与素材级（单张中位）**都算**。
典型反直觉：游戏级看着很好，素材级中位只在中下游 → 真瓶颈是素材平均水准，不是整体效率。

### 4. 游戏名变体不合并会算出假结果
同一游戏在大盘表里常有多个名字。先 `GROUP BY 游戏名` 看全部变体，用 `config.benchmark.aliases` 合并，
否则会算出某月 CTR≈0 的假结果。

### 5. 人群效率对比必须带曝光量
只给 CTR 不给分母 = 隐藏「这个人群其实没多少量」，是误导。
格式：`分层X CTR X.XX%（曝光 XXw）vs 分层Y ...`。

## 二、配置类

### 6. 显式 `--config` 传错路径会直接报错（不是 bug，是保护）
脚本**不会**悄悄回退到示例配置。看到「指定的配置文件不存在」就去核对路径。
未显式指定且 `config.json` 不存在时，才会回退示例并打印提示。

### 7. `segments` 与源表取值不一致 → 分层分析全空
`config.taxonomy.segments` 必须与源表「广告类型」列的实际取值**完全一致**。

### 8. `source.mode` 选错 → 做不了分层
`market_table`（平台大盘表）通常没有分层字段。要做用户分析，用 `own_ledger` 或从广告后台导出补充。

### 9. `cdn_base` / `referer` 没换 → 图片下载全失败
示例域名是 `cdn.example.com` 占位，务必换成你们平台的真实图片域名。

### 10. 档期日期是推断值 → 必须向业务确认
`config.nodes` 的日期每次复盘前确认，确认后只改配置，脚本不动。

## 三、打标类

### 11. 用广告文案猜画风
画风/元素/福利**只能逐张看图判读**，文案只作辅助线索。图片缺失标「待人工」+低置信度，绝不臆断。

### 12. 图片读图缓存去重
同一张图第二次读可能返回 "unchanged" 看不到内容。
→ 复制文件并在 JPEG 头插入 COM 段生成副本再读。

### 13. 同链接多条记录回填错
`label_merge.py` 映射必须保留**首次出现**的 rowid（与图片文件名一致），否则回填大面积为空。

### 14. 多选字段用等值分组
画面元素是多维，「包含」口径逐项筛，一条记录可计入多个组；结论里要说明组间样本重叠。

### 15. 标签拆太细
拆完样本个位数 → 结论不可信。新增类别前答「四问」，尤其第 4 问（样本够不够）。

---

## 四、在线表格 / 文档类

### 16. 命令行超长
一次写几百条报 `WinError 206` → 按 **50–80 条/批**拆分（`--batch`）。
长表追加报 `640463` → 按 **25 行/块**分批。

### 17. 本地文件导入被拦截
`doc import` 传本地 xlsx 会被安全策略拦。改用在线新建 + `cells batchset` 写数据。

### 18. 合并与表格样式互斥
要合并的行必须留在 `table style` 范围之外（样式从表头行开始）。两个方向都报错。

### 19. `replace` 后旧 block_id 失效
`blocks update replace` 返回 `new_block_id`，用旧 id 继续操作会**静默失败**（status=None，无报错）。
→ 改一批后重新拉块列表再继续。

### 20. 接口返回成功 ≠ 验收通过
五项断言（L1 结构 / 样式范围 / 尺寸 / 样式边框 / 数据不变）全过才能报完成。

### 21. 用户可能正在手动改表
读到的值和上次写入不一致，先怀疑用户在手改，**不要盲目覆盖**，问了再动。

## 五、报告 / 叙事类

### 22. 报告叙事尺度没确认就写
给更上层看的报告若写了「垫底 / X 分位 / 排名」容易被打回。
先问一句「这份给谁看、能不能写排名」，用 `report.narrative` 控制。

### 23. 对标对比只给 CTR 不给曝光
隐藏分母 = 误导。某维度没优势就删掉该对比，宁可少写。

### 24. 扎心数据算都不算
用 `positive_only` 时，排名/分位/与头部差距**仍要算出来留档**，
只是不进报告，交付时口头/私信告知业务方本人。「不隐瞒，但不写进给更上层看的报告」。

### 25. 文档留旧版内容
口径升级后必须**替换**旧章节，不要「新增一节 + 保留旧节 + 一句『现行见第 X 节』」。
业务方看到的就是旧结论。修订说明类章节定稿即删。见 `references/doc-sync.md`。

## 六、资源需求表类

### 26. 把全景表发给合作方
全景表是内部推演底稿，太重。对外只发精简需求表。

### 27. 单元格写理由 / 星期
只填结论（「X月X日」），不写「为什么这天」。理由在对话里说。

### 28. 派生素材排在 T 之前（因果错误）
切片 / 合集只能在活动结束后才存在，DDL 挂 T 之后。这不是排期松紧，是因果顺序。

### 29. 把规则举例当排他
规则里的举例通常是举例、非排他。找不出依据标「需运营评定」，别替规则做解释。

### 30. 擅自改用户定稿的表
核查发现问题，报给用户，**由用户决定改不改**。

## 七、通用工作习惯（跨 skill）

### 31. 整合资料别通读
先建地图（只登记元信息）→ 按需取用 → 每步留痕。一上来全读，时间花光还抓不住重点。

### 32. 分头做完不合稿
并行子任务最容易口径对不上。**合稿前必须先互相对齐**，每块产出带出处。

### 33. 删前不问
归档信息看着没用，可能是别人还在用的锚点。反复确认无用后，先列清单、向用户确认，同意再删；
实体文件只进回收站，不直接删。

### 34. 原表只读 / 对外产物带本地路径
打标结果写**新建**子表；对外产物只放 CDN 网址，禁止 `C:\...` 之类本地路径。
